Ratatui (_ˌræ.təˈtu.i_) is a Rust crate for cooking up terminal user interfaces (TUIs). It provides a lightweight, composable toolkit of widgets, layouts, and styling primitives for building text-based applications that run entirely inside a terminal — dashboards, CLIs, games, data explorers, and more. Ratatui was forked from the [tui-rs](https://crates.io/crates/tui) crate in 2023 and has since grown into an active, well-maintained project with a vibrant ecosystem.

## How Ratatui Renders

Ratatui is built on **immediate-mode rendering with intermediate buffers**. On every frame your application must describe the entire UI from scratch — you call `terminal.draw(...)`, pass a closure that renders all widgets to a `Frame`, and Ratatui diffs the resulting buffer against the previous frame before flushing only the changed cells to the terminal. There are no retained widget objects that update themselves; your render function is the single source of truth for what appears on screen.

This model keeps the library small and predictable. State lives in your application; Ratatui handles the diffing and the I/O.

<Note>
  **Which crate should I add as a dependency?**

  - **Building a terminal app?** Add `ratatui`. It re-exports everything you need — widgets, layout, backends, and the `init`/`run` convenience functions — and is the recommended starting point for application developers.
  - **Publishing a widget library?** Depend on `ratatui-core` instead. It exposes the stable `Widget` trait and core types without pulling in backend or widget implementation crates, keeping your library's dependency footprint minimal.
</Note>

## The Modular Workspace

Starting with Ratatui 0.30.0 the project was reorganised into a modular workspace. The `ratatui` crate remains the single entry point for applications — it re-exports every piece you need — but the underlying code is split into focused crates that can be depended on individually when necessary.

## Application Structure

Every Ratatui application follows the same three-phase loop:

1. **Initialize** the terminal — enter the alternate screen, enable raw mode, install the panic hook.
2. **Loop** — draw the UI, handle input events, update application state.
3. **Restore** the terminal — leave the alternate screen, disable raw mode.

The `ratatui::run()` function handles phases 1 and 3 automatically. You provide the loop. See the [Quickstart](/quickstart) guide to write your first app in under a minute.

## Who Should Use Which Crate?

| Scenario | Recommended dependency |
|---|---|
| Building a terminal application | `ratatui` |
| Publishing a reusable widget library | `ratatui-core` |
| Only need the built-in widgets as a dependency | `ratatui-widgets` |
| Need backend-specific APIs directly | `ratatui-crossterm`, `ratatui-termion`, `ratatui-termina`, or `ratatui-termwiz` |
| Want `constraint!` / `line!` / `text!` macros | `ratatui-macros` (already included via the `macros` feature in `ratatui`) |
