Widgets are the core rendering unit in Ratatui. Every piece of visible UI—a paragraph, a border, a list, a chart—is a widget. The library defines two stable traits (`Widget` and `StatefulWidget`) and one unstable trait (`WidgetRef`), each designed for a different use pattern. Understanding when to use each makes your code both ergonomic and composable.

## The `Widget` Trait

`Widget` is the fundamental rendering contract. Any type that implements it can be passed to `frame.render_widget()`:

```rust
pub trait Widget {
    fn render(self, area: Rect, buf: &mut Buffer)
    where
        Self: Sized;
}
```

The method takes `self` by value (consuming the widget), receives the `Rect` to draw into, and writes directly into the `Buffer`. That's the entire interface.

Ratatui ships with a blanket implementation so that bare strings can be rendered as widgets without any boilerplate:

```rust
// &str and String both implement Widget
frame.render_widget("Hello World!", frame.area());
frame.render_widget(format!("Count: {}", n), area);
```

### Implementing `Widget` for Your Type

The simplest custom widget defers all rendering to existing Ratatui primitives:

```rust
use ratatui::buffer::Buffer;
use ratatui::layout::Rect;
use ratatui::style::Stylize;
use ratatui::text::Line;
use ratatui::widgets::{Block, Paragraph, Widget};

struct Greeting<'a> {
    name: &'a str,
}

impl Widget for Greeting<'_> {
    fn render(self, area: Rect, buf: &mut Buffer) {
        let block = Block::bordered().title("Greeting");
        let inner = block.inner(area);
        block.render(area, buf);

        let text = format!("Hello, {}!", self.name);
        Paragraph::new(Line::from(text).bold())
            .centered()
            .render(inner, buf);
    }
}

// Usage:
frame.render_widget(Greeting { name: "Alice" }, area);
```

### Implementing `Widget` for `&MyWidget`

When your widget owns no consumed data and you want to reuse the same instance across multiple draw calls or render it in multiple areas, implement `Widget` for a reference:

```rust
use ratatui::buffer::Buffer;
use ratatui::layout::Rect;
use ratatui::widgets::{Block, Widget};

struct Counter {
    value: u64,
    label: String,
}

// Implementing for &Counter instead of Counter — no consumption.
impl Widget for &Counter {
    fn render(self, area: Rect, buf: &mut Buffer) {
        Block::bordered()
            .title(self.label.as_str())
            .render(area, buf);
        // Additional rendering with self.value …
    }
}
```

This pattern is recommended when your widget holds data immutably and multiple renders are expected. All built-in Ratatui widgets implement `Widget` for `&Self` since version 0.26.

## The `StatefulWidget` Trait

`StatefulWidget` is for widgets that need to track mutable state across frames—scroll position, selected item index, progress, etc. The state lives outside the widget and is threaded through each render call:

```rust
pub trait StatefulWidget {
    type State: ?Sized;
    fn render(self, area: Rect, buf: &mut Buffer, state: &mut Self::State);
}
```

### Implementing `StatefulWidget`

```rust
use ratatui::buffer::Buffer;
use ratatui::layout::Rect;
use ratatui::style::Stylize;
use ratatui::text::Line;
use ratatui::widgets::{Block, Paragraph, StatefulWidget, Widget};

struct ProgressBar {
    label: String,
}

struct ProgressState {
    current: u16,
    total: u16,
}

impl StatefulWidget for ProgressBar {
    type State = ProgressState;

    fn render(self, area: Rect, buf: &mut Buffer, state: &mut ProgressState) {
        let block = Block::bordered().title(self.label.as_str());
        let inner = block.inner(area);
        block.render(area, buf);

        let filled = (inner.width as u32 * state.current as u32 / state.total as u32) as u16;
        let bar = "█".repeat(filled as usize);
        Paragraph::new(Line::from(bar).green()).render(inner, buf);
    }
}
```

Store the state in your application and pass a mutable reference on each draw pass:

```rust
struct App {
    progress: ProgressState,
}

impl App {
    fn render(&mut self, frame: &mut ratatui::Frame) {
        frame.render_stateful_widget(
            ProgressBar { label: "Loading".to_string() },
            frame.area(),
            &mut self.progress,
        );
    }
}
```

## `WidgetRef` (Unstable)

`WidgetRef` is an unstable trait introduced in Ratatui 0.26. It renders by reference rather than by value, which enables storing heterogeneous widgets in a `Vec<Box<dyn WidgetRef>>` and iterating over them without knowing their concrete types at compile time:

```rust
// Requires enabling the `unstable-widget-ref` feature flag
use ratatui::widgets::WidgetRef;

let widgets: Vec<Box<dyn WidgetRef>> = vec![
    Box::new(Paragraph::new("First")),
    Box::new(Block::bordered()),
];

for widget in &widgets {
    widget.render_ref(area, buf);
}
```

<Warning>
`WidgetRef` is behind the `unstable-widget-ref` feature flag and its API may change before stabilization. Prefer implementing `Widget for &MyWidget` for stable code.
</Warning>

## Built-in Widgets

All built-in widgets live in `ratatui::widgets`. The table below lists every widget along with its primary use case.

| Widget | Module | Use case |
|--------|--------|----------|
| `Paragraph` | `widgets` | Styled, wrapped, aligned text |
| `Block` | `widgets` | Bordered container with optional title and padding |
| `List` | `widgets` | Scrollable list with optional selection highlight |
| `Table` | `widgets` | Tabular data with headers and row selection |
| `Chart` | `widgets` | Line charts with datasets and axes |
| `BarChart` | `widgets` | Vertical or horizontal bar charts |
| `Gauge` | `widgets` | Progress bar with optional label |
| `LineGauge` | `widgets` | Single-line progress bar |
| `Sparkline` | `widgets` | Compact inline bar chart |
| `Tabs` | `widgets` | Tab bar for navigating between views |
| `Canvas` | `widgets` | Free-form drawing (shapes, maps, text) |
| `Calendar` | `widgets` | Monthly calendar view |
| `Clear` | `widgets` | Clears a region of the buffer |
| `Fill` | `widgets` | Fills a region with a single cell |
| `Scrollbar` | `widgets` | Overlay scrollbar for any scrollable area |
| `Padding` | `widgets::block` | Insets inside a `Block` |

### Stateful Widgets

The following built-in widgets use `StatefulWidget` and require a companion state type:

| Widget | State type | State tracks |
|--------|-----------|--------------|
| `List` | `ListState` | Selected index, scroll offset |
| `Table` | `TableState` | Selected row/column, scroll offset |
| `Scrollbar` | `ScrollbarState` | Position, content length, viewport size |
| `Calendar` | — | (stateless) |

### Quick Examples

<CodeGroup>

```rust Paragraph
use ratatui::style::Stylize;
use ratatui::text::Line;
use ratatui::widgets::{Block, Paragraph, Wrap};

let paragraph = Paragraph::new(vec![
    Line::from("First line".bold()),
    Line::from("Second line".italic()),
])
.block(Block::bordered().title("Info"))
.wrap(Wrap { trim: true })
.centered();

frame.render_widget(paragraph, area);
```

```rust List
use ratatui::widgets::{List, ListItem, ListState};

let items = vec!["Alpha", "Beta", "Gamma"]
    .into_iter()
    .map(ListItem::new)
    .collect::<Vec<_>>();

let list = List::new(items)
    .highlight_symbol(">> ")
    .highlight_style(ratatui::style::Style::new().bold());

let mut state = ListState::default();
state.select(Some(1)); // select "Beta"

frame.render_stateful_widget(list, area, &mut state);
```

```rust Block
use ratatui::symbols::border;
use ratatui::widgets::Block;

let block = Block::bordered()
    .title("Panel")
    .border_set(border::ROUNDED);

frame.render_widget(block, area);
```

```rust Table
use ratatui::layout::Constraint;
use ratatui::widgets::{Cell, Row, Table};

let rows = vec![
    Row::new(vec!["Alice", "30", "Engineer"]),
    Row::new(vec!["Bob", "25", "Designer"]),
];

let table = Table::new(rows, [
    Constraint::Length(10),
    Constraint::Length(5),
    Constraint::Fill(1),
])
.header(Row::new(vec!["Name", "Age", "Role"]).bold());

frame.render_widget(table, area);
```

</CodeGroup>

## Nesting Widgets

Widgets compose naturally. Use `Block::inner()` to get the inner area after a border, then render another widget inside:

```rust
use ratatui::buffer::Buffer;
use ratatui::layout::Rect;
use ratatui::widgets::{Block, Paragraph, Widget};

struct Card {
    title: String,
    body: String,
}

impl Widget for Card {
    fn render(self, area: Rect, buf: &mut Buffer) {
        let block = Block::bordered().title(self.title.as_str());
        let inner = block.inner(area);
        block.render(area, buf);
        Paragraph::new(self.body).render(inner, buf);
    }
}
```

## Rendering `Option<W>`

Ratatui provides a blanket `Widget` implementation for `Option<W>` where `W: Widget`. If the option is `None`, nothing is rendered:

```rust
let maybe_error: Option<Paragraph> = if has_error {
    Some(Paragraph::new("Error!").red())
} else {
    None
};

frame.render_widget(maybe_error, error_area);
```
